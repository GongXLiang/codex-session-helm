# 能力边界与最小验收

在首次使用新宿主、升级工具或承诺自动续接前读取。这里区分公开文档、现场工具 schema、实际行为测试和未验证事项；同名功能不自动等价。

## 1. 能力检查

先发现当前工具并记录宿主与可用操作：创建、fork、发送、读取、等待、分组、停止、归档及工作区隔离。create_thread 返回真实 threadId 后才测试后续动作。侧栏 API 不等于嵌套生命周期 API，协议里的父子字段不保证可设置任意任务关系。

工具不可用时报告具体缺口；可以继续准备任务卡、验收方法和手动续接说明。只有原生能力确实不能满足已授权目标时才提出薄适配器，不自行启动另一套 App Server 并假定能接管桌面活动会话。

## 2. 分层验收

| 检查 | 有效证据 | 不能据此声称 |
| --- | --- | --- |
| 接口存在 | 现场工具定义或本机导出的 Schema | 桌面实际联动成功 |
| 创建与分组 | 返回真实ID，列表读回成员和顺序 | 折叠已验证、具有原生父子关系 |
| 主动回报 | 执行者真实发送，主管原先空闲，随后出现新回合并读取报告 | 应用退出后仍保证唤醒 |
| 忙碌时消息 | 发送时目标active，后续读回相同事件及处理证据 | 所有并发量与宿主都不会丢消息 |
| 旧版和重复回报 | 真实版本记录、通知、主管裁决与产物对照 | 仅检查字符串格式就验证了去重 |
| fork | 对指定源fork后读回实际历史、文件环境和是否启动 | fork隔离了文件、继承了全部隐含配置 |
| 停止／归档／恢复 | 对隔离目标执行，核对真实状态与产物保留 | 停止消息立即中断、归档没有连带影响 |
| 重启恢复 | 获授权重启宿主后核对状态与通知 | 仅从文件恢复一次就证明宿主重启不丢事件 |

普通任务只做与风险相称的检查。开发本工作流时使用专用测试组和临时目录；测试提示保持真实、可读，消息附人类授权来源。默认不为验收关闭有其他工作的应用，不碰既有项目会话，不把测试通过自动记入项目认可成果。

## 3. 行为用例

1. 两个独立任务乱序回报，只有必需的当前版本全部验收后才执行依赖步骤。
2. 同一逻辑结果重复通知、旧派发版本晚到，都不覆盖有效状态或重复推进。
3. 执行者需要输入、审批或被中断，回合结束不被判定为成功。
4. 回报投递失败或状态不明，保留文件并查证；不盲目重建会话或反复发送。
5. 主管在新回合从状态文件恢复，不重新运行已有有效成果；主管更换后只有一个当前责任人。
6. 显示移组不改变依赖；解除关联的未完成任务不会悄悄满足决策门。
7. fork、停止和归档分别验证，精确记录真实影响范围。应用重启、跨主机、云端另测。

## 4. 参考来源及证据等级

- [Claude Desktop 更新日志](https://claude.com/docs/cowork/changelog)：功能出现与支持环境。
- [Desktop 会话任务卡](https://code.claude.com/docs/en/desktop#start-a-task-that-claude-suggests)及[跨桌面会话](https://code.claude.com/docs/en/desktop#work-across-sessions)：公开用户流程。
- [Claude 跨会话消息](https://code.claude.com/docs/en/cross-session-messaging)：另一消息通道的投递、通知和限流，不直接当作 Codex 或 Desktop 专用通道规则。
- [Codex App Server](https://learn.chatgpt.com/docs/app-server)：线程、回合、事件和section协议；实际可用性仍核对宿主。

用户提供的 Claude 会话工具／提示快照属于版本线索。固定预览长度、提案数量、自动唤醒例外和detach细节未经当前验证，不写成跨产品常量。第三方界面记录用来寻找入口，不替代本机验收。

## 5. 当前验证记录

验证日期：2026-11-11。环境为 Windows 本地 Codex 桌面原生会话工具；本机 CLI Schema 版本为 0.167.0，不能据此推定桌面客户端版本。具体会话 ID、报告和检查快照保存在本次升级验收记录，不固化为 Skill 的运行地址。

已实测：

- 创建独立主管和两个执行会话；真实 ID 可寻址。创建时标题有未保存的情况，经 set_thread_title 后读回正确。
- 主管置顶、执行者自定义分组、全量成员排序和移组；这些证明组织操作，不证明折叠按钮或审批请求自动显露。
- 一次 sectionId:null 的移出调用返回成功，但随后仍读到旧组成员；显式 sectionId:"chats" 后读回已移出。运行时必须复核实际结果。
- 主管到执行者的派发与修订、执行者回报唤醒空闲主管、主管忙碌时收到并处理其他报告。此处只覆盖本地测试中的消息量和交错顺序。
- 两项有效报告独立验收齐备后才生成下游；旧版本、重复通知及返工后再到达的旧报告均未覆盖有效结果。
- NEEDS_INPUT 阻塞报告被正确识别：执行者回合结束不等于任务完成，未满足依赖未放行。
- 同一主管的新回合按实际文件恢复，已生成下游文件的 SHA256 与最后写入时间保持不变。
- 接收方先核对并确认、原主管释放职责后才激活新主管；有效版本、去重事件和未完成依赖随状态接续，来源快照保持不变。工作流层解除关联后，任务仍记为未完成，下游仍阻塞；向新主管重投原阻塞通知后，只登记迟到事件，没有恢复调度或重复推进。
- 对空闲会话进行 same-directory fork，读回继承历史及相同工作目录；未发新任务时没有自行重跑。叶会话归档、恢复后历史仍可读取，原执行会话仍在活动列表。归档后的 ID 可能保留在 section 成员记录，恢复后可能显示 notLoaded。
- 归档本次普通 fork 的来源会话后，fork 会话仍在活动列表，没有观察到连带归档；仅限本次创建方式与宿主。最终逐项核对四个测试会话均已归档、测试分组已删除，历史与本地报告保留。

仍需单独验证：折叠／展开及阻塞请求自动显露、真实停止／中断、宿主重启与长期后台、跨主机和云端、worktree 隔离、真实审批事件、多层委派、投递丢失与并发压力。当前没有发现可直接折叠或停止的原生桌面工具；不得因本地消息测试成功而声称这些能力已支持。交接和解除关联按工作流记录实现，不声称已改变原生父子关系或取消宿主回调。
