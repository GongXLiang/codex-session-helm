# 状态检查与看板

本文介绍不启动服务的经典模式。多个项目需要自动更新时，改用[多项目运行](多项目运行.md)：SQLite 为唯一进度账本，`export` 生成的 v1 JSON 只作本检查器的输入，不再手工维护。原生右侧浏览器面板可承载本地实时页面；Visualize 静态输出不承担后台采集。

`scripts/helm.py` 是可选的 Python 3.10+ 标准库工具：检查依赖、建议下一批、输出 Markdown 表格和 Mermaid 图。无需安装依赖，不连接桌面、不发消息、不改状态、不作验收。小任务无需使用。

命令行结果、错误信息和生成文件使用 UTF-8，避免 Windows 宿主默认编码不同导致中文输出失败。

## 一个权威入口

沿用项目既有状态文件。已有 Markdown 状态且人工足够维护时，直接在其中更新简明任务表，不另外建立 JSON 状态库。决定使用工具时，将 JSON 明确指定为当前任务状态的唯一权威入口；计划仍记录主张与裁决依据，生成的看板只供阅读。`updated_at` 是状态最后核实时间，生成看板不会让旧状态自动变新。

最小示例见[演示状态](../examples/demo-state.json)及[生成看板](../examples/demo-board.md)。示例为虚构任务，不能当作真实授权或验收。

## 使用

在 Skill 目录运行，把示例路径换为项目实际状态文件：

```sh
python scripts/helm.py check examples/demo-state.json --check-files
python scripts/helm.py ready examples/demo-state.json
python scripts/helm.py board examples/demo-state.json --output examples/demo-board.md
python -m unittest discover -s tests -v
```

`check` 和 `ready` 输出同一份检查与建议；看板在不支持 Mermaid 的阅读器中仍有完整表格。`--output` 仅允许用于看板，不允许覆盖输入状态。普通检查不写文件；显式输出会更新指定看板文件，使用前确认它确实是派生文件。

退出码：0 表示声明结构可用，1 表示存在运行中写入冲突或“已验收但依赖失效”，2 表示输入格式／依赖图／证据路径等错误。退出码 0 不表示任务已完成、可跳过现场检查或已经得到用户授权。可选 `--check-files` 仅核实报告及验收文件存在，不核实内容正确。

## 状态字段

| 字段 | 约定 |
| --- | --- |
| schema_version | 当前为整数 1 |
| workflow_id、updated_at | 工作流标识、带时区的 ISO 时间 |
| concurrency_limit | 本轮约定的并发上限，正整数 |
| case_sensitive_paths | 明确 true/false；按实际文件系统决定 |
| tasks | 当前任务列表；id 唯一，title 可读，version 为正整数 |
| status | planned / running / reported / accepted / needs_revision / waiting_input / waiting_approval / failed / paused / detached |
| run_state | unknown / active / idle / notLoaded / interrupted / failed；缺省 unknown，不将空闲等同于完成 |
| depends_on | 必填数组；每项为 `{"id":"T01","version":1}`，无依赖为 `[]` |
| workspace | 必填的规范化工作区标识，包含真实 hostId 与实际根目录；同一个物理目录必须使用相同标识 |
| write_paths | 必填数组，工作区内具体相对路径；`.` 是整个工作区，`[]` 是只读；不允许通配符或 `..` |
| priority | 可选非负整数，越小越优先，缺省 0；同优先级先考虑能解除更多后续阻塞的任务 |
| report、review | 相对于状态文件目录的证据路径；accepted 必须都有，实际验收由主管完成 |
| reason | 阻塞、失败、暂停、解除关联或待修订时必填 |

共享状态还可保存 threadId、hostId、turnId、授权来源、事件去重记录、等待 cursor、检查点和当前主管；工具不解析这些扩展字段，但主管恢复时必须核对适用信息。任务执行者不得擅自把自己改成 accepted。

## 检查边界

工具识别缺失依赖、重复ID、循环、旧版本及传递影响、运行中声明写入范围重叠。上游撤销验收时，已验收下游及其后继也会提示待复核。ready 只建议 planned 且依赖已有效验收、名额和声明写入范围允许的任务。

路径冲突检查是声明范围的字面比较：调用者必须先解析大小写别名、联接、符号链接、映射盘与远程路径，使实际相同工作区有相同标识。文件锁、真实进程、资源占用、内容正确性、科学主张和消息可靠性不在此工具能力内。任何建议在派发前都要与桌面实际状态和权限对照。
