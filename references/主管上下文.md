# 主管在多个项目之间切换

这套机制减少主管反复携带项目正文，并阻止明显的错项目、错版本操作。它不会清空模型已经读过的聊天历史，也不等于操作系统权限隔离。

## 默认只看全局摘要

`helm_runtime.py --db DB portfolio` 返回每个项目的目标、有效验收数、审查积压、最新检查点、待决定事项和待对账派发。不要把所有项目的完整报告拼进主管提示词。第一次读取和上下文压缩后，先从这里恢复，不靠对项目名字的印象。

项目正文分三层：

- 项目计划和规则是事实来源，留在项目自己的目录。
- 上下文摘要保存本项目目标、规则、术语、有效决定、未决问题和下一步，引用本项目文件及其 SHA-256。
- 切换检查点保存刚完成的核验、下一步和未决问题。它是主管写下的工作摘要，不能替代任务裁决或原始证据。

## 登记和更新项目摘要

按 [project-context.json](../examples/project-context.json) 生成项目自己的摘要。sources 是项目相对路径；运行工具自动补上项目 plan，并拒绝跨目录引用。单项长度和总长度有限制，详细材料只留入口。`expected` 是当前摘要版本，首次为 0；并发或交接后不能覆盖未读过的新版本。

```powershell
python $helmScript --db $helmDb --owner $helmOwner --epoch 1 save-context --project data --capsule 'D:\work\data\context.json' --expected 0
python $helmScript --db $helmDb --owner $helmOwner --epoch 1 focus --project data --output 'D:\work\data\focus.json'
```

主管实际阅读 focus 返回的内容，确认目标、定义、当前任务版本和上次检查点；再用 `context --project ... --workflow ... --task ...` 取当前任务的详细卡片与依赖。focus 只加载一个项目，摘要包不超过 24,000 字符。达到上限时收缩摘要和当前工作范围，不静默截断关键规则。

新建账本采用 schema 2。`prepare`、`revise`、`review` 都检查当前项目上下文；切错项目、摘要源文件改变、任务版本或回报变化时，旧加载状态失效。先读新证据并更新摘要，再重新 focus。源文件变动不能靠重复 focus 悄悄承认，必须通过 `save-context` 登记新版本。

任务卡应同时带上 project/workflow/task/revision/attempt、context_version 和源文件入口。执行者只读自己的卡与已验收依赖；收到其他项目摘要时报告错路由，不自行合并。

## 切换和续接

裁决写入后，或暂时中断审查前，保存检查点。审查未结束时先 release，不把领取令牌带到另一项目。

```powershell
python $helmScript --db $helmDb --owner $helmOwner --epoch 1 checkpoint --project data --summary '已独立核对首轮结果，尚缺边界样例' --next '领取 T02 回报并核对新增样例' --question '新增样例是否覆盖空输入'
python $helmScript --db $helmDb --owner $helmOwner --epoch 1 focus --project code
```

未保存检查点就切项目会被拒绝。项目规则改版后，旧检查点仍保留，但包中 `checkpoint_is_current` 会显示它是否属于当前摘要版本。恢复时以新的规则和账本裁决为准。

每次项目切换，只把上一项目的一两句工作结论留在主管常驻摘要；不要复述整段报告。若审查需要大量日志、多个长文档，或已经出现定义串线，让已获授权的独立复核会话只读取该项目材料。主管接收带版本和证据入口的简报。工具不能保证模型永不混淆，独立会话是进一步隔离详细推理的手段。

## 新主管接手

handoff 增加 epoch、清除旧 focus、把已领取报告放回队列。新主管只需 portfolio、当前项目的 focus、完整报告和证据，并重新核实原生会话状态；旧主管和旧 token 均不能继续裁决。未记完的口头结论不算已验收。实际应用退出后是否自动恢复会话和服务，需要另行现场验证。

## 旧账本升级

schema 1 可继续读取和使用原有工作流，**没有新增上下文门禁**。停止该账本的服务及写入者后，显式升级并保留一致性备份：

```powershell
python $helmScript --db $helmDb --owner $helmOwner --epoch 1 upgrade --backup 'D:\work\coordination\before-context-upgrade.sqlite'
```

备份不覆盖已有文件；备份期间账本变化会拒绝升级。升级后为每个项目登记摘要，再继续派发。不要修改 SQLite 表来跳过门禁。
