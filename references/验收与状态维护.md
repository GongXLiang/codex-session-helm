# 主管验收、修订与文件维护

收到回报、准备补充任务或恢复长任务时读取。表单在[回报与验收模板](../assets/回报与验收模板.md)。

## 1. 主管实际检查什么

不要只转述执行者自评。根据任务风险选择必要检查并写清检查范围：

- 产物是否对应任务卡的输入、步骤、派发版本和验收条件。
- 关键数字或行为能否独立复核；自检是否只重复同一实现。确定性基线、浮点容差、视觉审阅分别按任务规则使用。
- 输入本身是否可信：版本、覆盖、缺测、单位、仪器或异常值是否改变解释。结果可重现不代表输入正确。
- 受保护数据、基线或旧稿是否按约定保持。核验应晚于最后一次可能影响它们的改动或重跑；必要时主管补做。任务记录和投递回执等允许更新的文件，不应机械纳入“冻结不变”。
- 图件是否实际查看，文字是否与证据范围对应；未完成的检查明确写“未检查”，不能预称已视觉验收。
- 偏离、失败和反例是否完整披露；补充诊断是否被误写成预登记检验。

不为轻微文字修改强制新增测试，不反复重跑已充分验证且未受新改动影响的部分。若检查发现数据问题，先标影响范围和暂停引用项，订正源产品须遵守本轮授权及保护约定。

## 2. 裁决与补充任务

裁决可为通过、部分通过、退回修订、证据不足暂缓或技术阻塞。分别记录宿主回合状态、任务报告状态、主管裁决和主张支持程度；有效阴性结果可以通过任务验收。idle、notLoaded 和 turnCompleted 都不直接代表任务完成；需要输入、审批或中断的回合不自动打开依赖。

返工优先使用原会话。列出已接受并保留的部分、未通过项及证据、本次修改范围、新旧定义、输出版本、复核方法。对补充任务顺序编号或增加派发版本；不要求无关产物全部重做。

口径变更先登记再实施；原结果依其性质重现或比较，并保留对照。看到新结果后才产生的解释保留事后性质。冻结基线失败时查明变化，不能重建基线掩盖差异。

## 3. 三类项目文件

| 文件 | 记录什么 | 责任 |
| --- | --- | --- |
| 权威计划 | 核心问题、主张、定义、任务卡、依赖、决策门及主管裁决 | 主管在已授权范围内维护 |
| 共享执行状态 | 工作流及任务、派发版本、原始派发者与当前主管、执行会话ID/hostId、创建与送达状态、等待集合、已处理事件、进度、验收结论、产物入口、下一步；分组与fork来源单列 | 主管保持当前摘要准确；执行者只按项目约定追加事实简报 |
| 各任务记录与回报 | 实际输入、环境、操作、产物、偏离、失败和验证证据 | 执行者在指定目录维护 |

沿用项目已有入口，不额外维护平行状态库。普通进展更新状态即可；对结论或路线有影响的裁决更新计划相关条款，并记录依据。

## 4. 验收后同步

1. 先依据实际证据作出裁决，明确哪些结果和主张被接受。
2. 在计划的审阅区记录：检查、偏离、结果要点、裁定、对后续任务的影响和证据路径。
3. 若改变现行定义、主张或任务卡，同时修改原位置或标“日期更正→新裁决位置”；保留有价值的原判断和失败。不能只在文末追加、让旧卡继续生效。
4. 更新共享状态的当前有效摘要，说明待验收、阻塞、被替代结果和允许或暂缓的任务。若计划同步未完成，明确标记，不能按旧卡派发依赖任务。
5. 按已登记的决策门判定；所需任务验收未齐时不擅自判成功。涉及新方向按用户约定交决定，不把未答复当确认。
6. 从更新后的文件整理下一任务 Context，列出已接受结果、适用条件、正确版本、反例、未决项和不能据此声称的内容。

若原登记检验结论为“无法判定”，主管采纳补充诊断作工作判断，应分别写清原检验、事后诊断和裁定理由，不改写原检验结论。

## 5. 当前有效摘要

共享状态可在顶部维护以下项目；项目若要求仅追加，则在末尾设置清晰的最新摘要并在入口指明位置：

```text
更新时间与当前授权范围：
权威计划及最新相关裁决位置：
已验收任务及证据入口：
进行中任务、派发版本、执行对话ID/hostId、当前主管：
创建／简报送达／运行状态、等待集合、最近cursor与已处理事件：
待验收／待修订／阻塞任务：
当前有效结论与限制：
已被替代或暂停引用的结果及原因：
待用户决定：
下一步允许／暂缓／不得启动的任务及条件：
```

历史段落中的“未开始”等内容明确属于历史，不能与当前摘要混淆。字段仅保留适用项，小任务不强制创建完整台账。

恢复时核对会话实际状态、当前报告版本和已验收记录，不重复运行已有有效产物。旧版或重复通知保留简短事件记录，不回退当前裁决；解除关联的未完成任务记为暂停或移交，不能从等待集合删除后就判定依赖满足。主管交接先确定唯一责任人并记录交接版本，用户直接介入执行会话的变更也要回填共享状态。具体协议见[桌面会话协议](桌面会话协议.md)和[嵌套会话与分组](嵌套会话与分组.md)。

## 6. 决策门记录

```text
决策门、日期与授权依据：
前置任务与主管验收记录：
预登记判据与计划位置：
出口：成功／失败／资料不足，及实际证据
主张保持、收窄、撤回或仍待核的范围：
计划具体更新位置：
下一批开展／暂缓／不做的任务及理由：
待用户决定与恢复入口：
```

## 7. 并发与恢复

默认主管统一更新共享文件；项目允许执行者追加时只写本任务事实并标“执行完成，待主管验收”。写前重读，不整文件覆盖他人修改；难以安全合并时让执行者保留简报由主管归并。

主管恢复先读当前状态、相关最新裁决与任务卡；执行者恢复先读其最新派发版本和自身任务记录。文件发生实质冲突时回查用户指令与证据，不仅按修改时间选一个版本。

保持 Skill 通用：项目路径、参数、科学结论与会话 ID 留在项目文件。本流程不自动授权修改长期记忆、原始数据或受保护版本。Git、下载、安装等按真实授权与适用规则处理，已有授权覆盖时不再另设确认门槛。
