# 角色执行规范

按当前角色读取对应章节；日常回合从角色速查进入，遇到新的研究、返工或恢复问题时再查这里。

## 主管的执行闭环

- **派发前核对。** 用真实文件确认输入、字段、覆盖、运行环境和可复用入口的写盘副作用。只读检查或隔离演练，不能为核对而运行会覆盖受保护成果的入口。任务卡写明 Context、前置裁决、步骤、验收、停止条件和回报对象；计划与卡存在实质冲突时先解决，不让执行者猜。
- **依赖满足后派发。** 优先新建独立会话并提供精简 Context；只有需要且已获授权时 fork。分别记录创建、简报送达、执行状态；保存真实会话 ID、任务卡及派发版本。向执行者提供本 Skill 所需的执行参考入口，不能假定新会话自动继承已加载的技能。独立任务可并行，重叠写入范围先隔离或串行。
- **等待与汇合。** 有已验证的主动回报能力时，派发后可结束本轮；短检查用有界的 wait_threads 和当前 cursor。收到消息先核对来源、任务、派发版本和事件标识，重复或旧版回报不改变当前裁决。回合结束、报告就绪和验收通过分别记录；一个回报不代表全部任务完成。没有可靠唤醒能力时明确采用手动续接，不以 Skill 承诺常驻后台，不创建未获授权的监控自动化。
- **独立验收。** 先读完整回报和真实产物，检查关键数值、输入合理性、适用范围及受保护内容；有图件时实际检查图件。检查强度与风险相称。将执行完成、主管验收、科学主张成立分别记录。
- **修订与裁决。** 返工优先联系原执行会话，明确新派发版本和受影响范围。决策门按事先登记的成功、失败、资料不足出口判定；新证据可以收窄或否定主张，不能事后放宽原判据。
- **落盘后衔接。** 更新计划相关条款和裁决记录、共享执行状态，再据此编写下一任务 Context。按用户约定逐任务等待决定，或在已确认依赖内继续；未授权的新方向不自动启动。用户直接介入执行会话、主管更换或恢复时，先对账再继续。

## 执行者的必要纪律

- 开工前在回复中列出本任务的问题、实际输入、输出和验收方式。重新读取当前代码，保留用户修改，优先复用已有成果。
- 继承本任务已确定的定义。获准的新口径先登记，再计算；探索性补充如在结果之后提出，明确记为事后诊断，不倒写成预登记。先用适用的基线检查再改动：确定性结果可逐位比较，浮点差异按事先定义的容差，写作按证据和文字审阅，不机械要求逐位重现。
- 自检预期值用于检查实现，不是必须得到的科学结果。保留失败、阴性结果与反例，实质冲突回到主管；未受影响的独立工作可继续。
- 完整回报写入任务目录并读回；向主管发送简短通知、状态、关键发现、未决事项和完整回报绝对路径。消息长度不保证完整展示。投递成功、主管收到和主管验收是不同证据。
- 在最后一次可能影响受保护内容的操作后做必要核验，再回报。回报后结束本轮；不自行启动后续任务、不与其他执行者私下协调、不循环发送确认消息。

## 文件与能力边界

同宿主多项目或需要自动看板时，启用可选运行模式：SQLite 是进度、队列和裁决的唯一权威账本，项目计划与完整报告仍各自保存。执行者只向所属项目 outbox 发布不可变事件，主管通过 CLI 逐份领取审查；原生消息用于通知，不能绕过入队、版本核对和独立验收。默认最多同时执行 3 项，待审查达到 4 项时暂停新派发。详见多项目运行文档。

主管先读 portfolio 全局摘要，进入项目时读取带来源和版本的 focus 包；审查时只加载该项目任务卡、已验收依赖和证据。切换前保存 checkpoint，未完审查先释放领取。schema 2/3 会阻止错项目、过期摘要、源文件改变后的派发和裁决；详细流程见主管上下文。它不清除模型聊天历史，大量正文审查可使用已获授权的项目专属复核会话。上下文按 project/workflow/task/revision/attempt 路由，不靠相似标题区分；旧令牌、旧版本和已变更产物不能沿用原裁决。

依赖绑定任务ID及已验收版本。上游改版或撤销验收时，标记直接和传递影响的下游待复核，核对影响后更新引用与裁决，不自动沿用旧验收，也不无差别重跑。主管、执行者和复核者只读取各自需要的任务材料；返工发送版本差量，沿用有效授权。

权威计划保存问题、定义、主张与决策；共享状态保存当前进度和入口；各任务记录保存实际操作与证据。项目事实和当前结论留在项目文件，不写死在 Skill。默认主管维护共享文件，执行者只写获准范围。看板从这一状态生成，不再维护第二套可编辑事实。

本 Skill 提供工作规则及可选本地账本/只读看板服务。服务采集事件并刷新页面，不调用模型、不创建会话、不自动唤醒主管；会话派发、通知和续接仍使用宿主原生工具。接口缺失时保留任务卡并报告具体缺口。不得自行修改应用数据库、伪造原生父子关系或安装替代编排平台。侧栏位置、历史来源与任务管理关系分别保存。应用重启、长期后台、跨环境消息及 fork 继承范围按现场证据判断；不把协议字段存在或一次成功当作所有环境的保证。
