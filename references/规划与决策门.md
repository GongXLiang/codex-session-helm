# 规划、任务卡与预登记决策门

在需要新计划或实质改变路线时读取。已有计划只补受影响部分，不强迫小任务使用完整章节体系。项目已有格式可继续沿用。

## 1. 规划阶段的产出

先读取项目规则、交接材料和关键原件，核对影响路线的输入与数字，识别可复用成果。只读核查不等于启动新一轮科学计算；当前模式允许时保存计划，否则在回复中交付计划。

复杂研究可按以下骨架组织，简单任务保留必要部分：

| 内容 | 应回答的问题 |
| --- | --- |
| 背景与当前定位 | 用户原始目标是什么？模型的延伸解释是什么？目前成果实际回答了什么？ |
| 核心问题与取舍 | 一句话写出主要问题；必要时比较候选路线、成本、风险和收敛方案 |
| 论证链或实现链 | 缺口→问题→可区分的解释或方案→所需证据→现有支持→剩余缺口→可达结论 |
| 主张或需求表 | 每一项如何检验、适用范围、反例和可否定条件是什么？ |
| 交付物职责 | 每个章节、图件、模块承担哪一步；旧成果保留、压缩、补验还是停用？ |
| 定义与参数 | 哪些继承、哪些新定、哪些只是实现细节？依据是什么？ |
| 任务与决策门 | 输入、输出、依赖、验收、失败出口及回到主管的条件 |
| 用户决定 | 仅集中询问会改变路线的事项；可给推荐选项，未回复不等于确认 |
| 验证与进展记录 | 任务、阶段和最终交付如何验收；后续裁决记录在哪里？ |

用简明标签区分已读原件、既有验收、推断与待验证事项；每个关键事实给出文件和具体位置。文献全文、摘要和二手转述不得混为同等依据。

## 2. 主张或需求表

| 编号与陈述 | 证据入口 | 支持范围 | 替代解释或风险 | 可否定条件 | 当前状态 | 必需性 |
| --- | --- | --- | --- | --- | --- | --- |
| 【可检验陈述】 | 【文件及位置】 | 【样本、时段、条件】 | 【其他解释】 | 【何种结果不支持】 | 【待检验／已支持／收窄／撤回】 | 【必需／可选】 |

科学任务区分观测、关联、过程解释与因果主张；工程任务区分实现存在、测试覆盖与实际使用效果。名称和结论不得超过证据能力。

## 3. 参数与判据登记

- **继承约定：**写清样本、时间窗、公式、单位、缺测与统计处理、基线版本及出处。执行者不得自行改变本轮已确定的科学或业务定义。
- **新定约定：**在用于正式检验前登记规则、依据与时间。依据可来自文献、实际覆盖、设计约束或可说明的领域判断；探索性选择标明探索性质，不编造来源。
- **实现选择：**与科学结论或需求定义无关的代码组织、常规排版等交执行者判断。
- **事后补充：**看到结果后提出的新检验可以开展，但必须标明提出时点和探索性质；不能用它替换原检验、消除失败或伪称预登记。

冻结是本任务的执行约定，不禁止主管在有证据且权限允许时修订。修订需保留原结果、记录依据，并给出新版本。

## 4. 任务卡派发前核对

使用配套任务模板，填入：任务目的、复用成果、输入输出、Context、前置裁决、步骤、检查方式、停止条件、回报对象与授权依据。

主管先检查：

1. 路径、字段、数据覆盖、样本与时间真的存在且适用；相关前置任务已通过必要验收。
2. 代码入口、导入语句或函数调用是否会写盘、下载或改配置。导入也可能有副作用；不能把“只导入”当成安全证明。
3. 优先使用能明确指定输出位置的安全接口；否则在隔离目录做最小必要适配，说明源代码及差异，避免无必要复制整条旧流程。
4. 验收有可观测判据；能独立手算或从已验收基线取得的值作为实现自检。不能把待研究的预期结论写成必须相等的答案。
5. 确定性结果可要求逐位一致；跨环境浮点使用有依据的容差；图像与写作用适合的视觉或内容审查。

核对不启动可能覆盖受保护成果的完整入口。发现实质缺口先补任务卡或回到用户约定的决策点。

## 5. 决策门

每个门写明所需任务及验收、判断的问题、预登记判据和三个出口：

| 出口 | 含义 | 应预先写出的安排 |
| --- | --- | --- |
| 成功 | 证据足以支撑下一阶段的前提 | 开展哪些任务，允许说到何种程度 |
| 失败 | 有效证据不支持关键前提 | 收窄主张、采用备用路线或停止哪条分析 |
| 资料不足 | 无法按原方法判定 | 缺什么、是否值得补、哪些成果可保留 |

成功不要求原假说一定成立；有意义的阴性结果可能完成研究任务。门由主管依原判据判定；涉及超出已确认范围的新路线时交用户决定。未齐的前置验收不能被“部分执行者已回报”替代。
