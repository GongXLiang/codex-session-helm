# 停止与重启验证

“停止”涉及模型回合、外部命令、文件写入三个层次；“重启恢复”涉及应用、会话历史和项目状态。分别核验，不能用发出“请停止”的消息或读到旧文件代替。

本地实测曾出现：用户点击停止后回合 interrupted，但该回合通过 exec_command 启动的 Python 进程仍写入输出。因而主管必须保留运行占用与写入保护，直到进程及输出也确认停止；已暂停的任务如果宿主或进程仍活动，状态记录 run_state 仍为 active。不要在旧进程未结束时启动续接副本。实际记录见[兼容性与验收](兼容性与验收.md)。

## 准备

只在已获授权的隔离测试会话与专用临时目录进行。先创建[恢复检查点](../assets/恢复检查点.md)，给演练设置时间上限，记录真实 threadId/hostId/turnId。测试进程按固定间隔写入可计数进度，输出只在测试目录；记录 PID、创建时间和用途，不启动无法归属的后台进程。应用退出前保存主管续接入口，避免检查本身丢失上下文。

原生工具无停止或退出能力时，由用户点击停止或退出重开；不能绕过工具限制控制应用。说明这是完成行为实测所需的操作，不重新索要已经覆盖的任务授权。不能为验证关闭用户其他重要工作。

## A. 真实停止

1. 确认测试回合 active、进程在运行、进度至少增长两次；记下停止前状态。
2. 使用支持的真实中断接口，或请用户点击测试会话的停止按钮。给模型发“停止”指令只属于协作消息，不视为真实中断。
3. 读回目标回合 interrupted 或现场等价状态；核查原进程身份，观察至少两个原进度间隔内是否仍有输出增长。回合中断和命令终止分别记结果。
4. 若进程仍在运行，判“回合已停、外部工作未停”，先处理本任务明确拥有的进程，再核查输出；不得把补救操作写成原生停止自动成功。清理只能针对已核验身份且在授权范围内的进程。
5. 将任务标暂停／待恢复，后继保持阻塞，保留已写入证据。恢复时从检查点继续一个未完成步骤，核对已完成步骤没有重复。

## B. 应用重启恢复

1. 保存已验收步骤A的产物校验值、待完成步骤B、状态与消息检查点。记录客户端主进程身份和启动时间；明确是否也要测试运行中的外部工作。
2. 让用户正常退出并重开应用。进程创建时间变化或其他可信启动证据证明真实重启；只换聊天页或新开回合不算。
3. 回到原会话后，用原生工具读取测试会话与最后回合，核对权威状态、版本、当前主管、未完成工作和消息送达记录。notLoaded 先读取或恢复，不能当作任务丢失或重新创建。
4. 继续B，保持A的内容和写入时间不变；报告／验收不得重复计数。验证一条重启后的合法派发或回报。
5. 区分“重开后按检查点恢复成功”与“应用关闭期间继续运行、消息保证不丢、自动唤醒”。后面三项需要各自实验，不能由前一项推断。

跨主机、云端、worktree 与长期后台运行独立列为未覆盖，除非确实在相应环境完成测试。报告写明日期、客户端版本、操作、观察、限制和脱敏证据入口。测试结束按授权归档测试会话，保留记录；归档不是停止。
